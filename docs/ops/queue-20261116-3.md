## 5. Collie 本身的问题（汇总）

1. **`--max N` 把 FIX 重跑也算进 N 里。** SPEC 12.2 原文：「`--max N` 限制本次最多跑 N 个批次（缺省不限；数的是 PASS 的批次，FIX 重跑不计）」。
   - 固定版本的 `src/run.ts:2600` 是 `if (ctx.max !== undefined && batchesRun.length >= ctx.max)`，而 `batchesRun` 每次运行都 push（`:2517`），FIX 的也算。
   - 这个检查只在 PASS 之后做，所以「FIX、FIX、PASS」在 `--max 2` 下也会在 PASS 后停。
   - 结果：本轮 b08 一次 FIX、一次 PASS 就到了上限，b09 没跑。以前的队列都是一次就过，所以没暴露。
2. **b08 删掉了 SPEC 14.9 的「`git pull` 连续失败 3 圈通知一次」**：`7bf4a6d` 删了实现；`572836a` 把守它的测试改写成不再断言，注释没改。
   - worker 没写进「偏离或疑问」，两次 reviewer 都没发现，变异检查也只覆盖 `arbiter` / `gate` / `evidence`。
   - 「改写与新行为冲突的旧用例不算删测试」这条豁免，正好被用来去掉一条并不冲突的断言（`v045-b08-r2.md` 第 4 段第 1 条）。
3. **worker 漏提交**：它 `git status` 看到 `M src/follow.ts`，却只 `git add` 了两个测试文件，然后汇报说 lint 通过。R2 用 `head_sha` 跑验收拦住了，工作区的脏文件也被救援提交。**这一条是 Collie 按设计起作用了**。
   - 只是 FIX 的结论行写的是规则 4（test #29 同义反复），lint 失败与 CI failure 要看别的行。
4. FIX 重跑的 task 里「上一轮代码提交」列了信封提交 `132bf2f`（它不是代码），却没列救援提交 `daec258`。worker 这次是自己发现的。
