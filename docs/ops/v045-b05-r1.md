## 4. Collie 本身的问题

1. **推送失败之后，汇报提交永远推不上去。**（实测）
   - SPEC 14.9 第 1 条要求「本地领先远端时每圈先 `git push`」。代码里只有两处推送：
     - `pushIfAhead`，只在 `case 'run'` 里调用（`src/follow.ts:734`）；
     - `retryPendingPush`，只在 `pendingPush === true` 时调用（`:645`），但新代码已经不再设置 `pendingPush`（`:752~757` 写回的状态里没有这一项）。
   - 而推送失败后 `handledBase` 已经记下，下一圈 `decide()` 判的是 `wait`，进不了 `case 'run'`。所以只要 next.md 不换基准，就再也不会推送。
   - **实测：** 我在 `/data/tmp` 的仓库副本里，把测试 #11 改成「3 圈推送失败 → 恢复远端地址 → 再走 3 圈」。结果本地有 `ops: report queue q-push-1 (base 04a5874bcf59)`，远端没有，`runContinue=1`，断言失败。副本已删。
   - 后果：R1 看不到汇报；通知只发过一次「推送失败，下一圈重试」，可下一圈并不会重试。
2. **推送失败的另一种情形：远端在队列期间前进了（例如 R1 推了 next.md）。**
   - 这时 `push` 因为不是快进而失败；之后每圈的 `git pull --ff-only` 也失败（本地多了一个汇报提交，已经分叉），连续 3 圈只通知一次 `pull`。
   - 本地的 next.md 永远停在旧的那一份，于是一直 `wait`。代码里没有 rebase，也不会把这种情况和网络失败区分开。（读代码得出，没有实跑）
3. **`npm ci` 失败不会被发现，失败的目录还会被一直复用。**
   - `preparePinnedR2` 不看 `spawnFn(['npm','ci'])` 的退出码（`:189`、`:194`）；缺省的 `defaultSpawn` 从不抛错，所以 `pinned:<sha>` 通知和退避都走不到。
   - 目录已经建好（`git worktree add` 成功了），下一圈 `existsSync` 为真就直接复用（`:171`），里面始终没有 `node_modules`。
   - 之后每次 preflight 都失败，进入退避，通知的失败项是 `unknown`：子进程没输出 JSON，失败项名字取不到。（读代码得出）
4. 汇报附录里的「preflight 末行」取的是 `preflight --smoke --json` 输出的最后一行，也就是 `}`，没有信息。
5. `defaultSpawn` 没有监听子进程的 `error` 事件。程序不存在时（比如 PATH 里没有 `npx`），`follow` 会直接崩溃，而不是返回一个退出码。
6. 小问题：退避状态 `retry` 不随基准提交清零。上一个基准失败留下的 `notBefore`（最长 60 分钟）会推迟新基准的第一次尝试。
