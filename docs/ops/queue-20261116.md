## 6. Collie 本身的问题（汇总，细节见各批次汇报第 4 段）

1. **`follow`：preflight 没过时每圈都通知、每圈都调 runner**；祖先检查失败同样如此。测试名写的是「notify once」，但测试只跑了失败的一圈（`v045-b04-r1.md` 第 4 段第 1 条）。
2. **`follow`：推送失败后下一圈会把整个队列再跑一遍**，原因是 `handledBase` 只在推送成功时才记（同上第 2 条）。
3. **`follow`：锁文件不同时 `npm ci` 实际执行的是 `npx tsx npm ci`**，失败被吞掉，接着进入第 1 条的循环（同上第 3 条）。
4. `follow`：「队列结束」通知里的 reason 是按退出码猜的，`limit` 会写成 `exhausted`；preflight 失败通知会带上 token 文件的绝对路径；`git pull` 失败被静默吞掉；整个队列期间没有任何输出。
5. **`report`：「开始」和「墙钟」在真实数据上永远是 `—`**。测试手工造了一个队列 journal 里的 `run.started`，真实的 R2 不写这一条（`v045-b02-r1.md` 第 4 段）。
6. **b01 的 worker 用了 200/200 轮**，`why` 看不出是否顶到上限（`v045-b01-r1.md` 第 4 段）。
7. 不变量「只有 `run.ts` / `evidence.ts` 访问 `.token_file`」连注释也算，b03 的 worker 为此改了注释措辞，并在汇报里如实写了（`v045-b03-r1.md` 第 4 段）。
8. 不带 `--smoke` 的 `preflight`（也就是队列开头的自动检查）查不出 token 过期，只查文件存在。2026-11-10 那次是文件丢了，这种情况它能查出来；token 过期则要靠 `follow` 先跑的 `--smoke`。
