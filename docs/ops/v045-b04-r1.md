## 4. Collie 本身的问题（读 `src/follow.ts` 得出，没有实跑 `follow`）

1. **preflight 没过时，每一圈都会再跑一次 `preflight --smoke`，并再发一次通知，不是「只通知一次」。**
   - `executeRun` 在 preflight 失败的分支（约 256~263 行）不看 `notified` 里有没有 `preflight:<基准>`，直接 `sendNotify`。
   - `decide()` 的判定表里也没有 preflight 这一行。`handledBase` 没记，所以下一圈仍判 `run`。
   - 结果：环境坏着的时候，**每 60 秒调一次 runner（`--smoke` 会调模型），往群里发一条通知**。
   - 测试 `preflight failure → notify once, does not record handledBase, retries` 只跑了失败的一圈就换成成功，没测第二圈失败时是否不再通知。
   - 「基准提交不是 HEAD 祖先」那一支（约 243~249 行）是同样的问题。
2. **推送失败之后，下一圈会把整个队列再跑一遍。**
   - 推送失败时，`handled: false`，`handledBase` 不记，只记了 `pendingPush: true`（约 466~470 行）。
   - 下一圈先重试推送；不论推送成没成功，都不补记 `handledBase`。
   - 接着 `decide()` 看到 `基准提交 ≠ handledBase`，又判 `run`，于是再起一次 `run --continue --max N`，再写一份汇报、再发一次通知。
   - SPEC 14.4 第 8 步是无条件把基准记为已处理，第 6 步只要求重试推送。
   - 另外，preflight 失败和祖先检查失败的分支也会被记成 `pendingPush: true`（同一处逻辑）。
3. **`package-lock.json` 和 HEAD 不同时，`npm ci` 实际不会执行。**
   - `defaultSpawn` 对所有参数都套一层 `npx tsx …`（约 492 行），所以 `spawnFn(['npm','ci'], dir)` 实际执行的是 `npx tsx npm ci`。
   - 这条命令的失败被吞掉了（「Best effort」）。固定版本目录就没有 `node_modules`，接着 preflight 失败，再进入第 1 条那种每圈都通知的循环。
