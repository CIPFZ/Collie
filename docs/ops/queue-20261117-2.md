## 5. Collie 本身的问题（汇总）

1. **一个 SDK 会话可以有不止一条结果消息，运行器只留最后一条。**
   - b13 的 worker：最后一次 `git push` 被自动转到后台，会话先结束一次（66 轮），推送完成的通知又触发了 1 轮，第二条结果消息覆盖了第一条（`src/runner/claude.ts` 循环里的 `result = message`）。
   - journal 的 `num_turns`、`usage`、`final_text` 都只是最后 1 轮的；花费是累计的，没错。
   - `why` / `report` 的「到上限」标注靠的就是这个轮数，这种情况下等于失效。
   - 和 v045-b14 是同一个函数、同一类问题，建议放在一批修（`v045-b13-r1.md` 第 4 段第 1 条）。
2. **重跑时上一轮的 `verdict.md` 仍在 reviewer 的工作目录里**（b12 只删了 `report.md`）。它不含 worker 的声称，但新 reviewer 能看到上一位的完整判断。路径排除只在提示词里，reviewer 用 `git show` / `git log -p` 仍能读到任何一轮的汇报（`v045-b12-r1.md` 第 4 段）。
3. b12 的 reviewer 在自己的 verdict 里写 `remote_has_head: false`，理由是「`git ls-remote` 未匹配」，而 R2 取到的是 true。reviewer 的工作目录可能连不上远端。不影响结论，但 reviewer 的证据和 R2 的不一致。
4. v045-b14 的第 3 条测试只覆盖「没有会话号」的情形；出错分支不看 `interrupted`（`v045-b14-r1.md` 第 4 段）。
